# El-Kīmiyā V8.0 — Multi-role Web MVP

## Install
Extract the patch in a temporary directory, then run `powershell -NoProfile -ExecutionPolicy Bypass -File <extracted>/run-v80.ps1 -ProjectRoot 'D:\el kimiya'`. The installer verifies exact V7.1 anchors, writes a private backup of changed existing files and lists created files in its manifest. No Android source, `.env`, PDFs, Git commits or Firebase deployment are modified. On source mismatch stop and inspect the diff; do not force overwrite. Existing dependencies must already be installed (`npm ci` if needed).

## Firebase console — same project, Spark plan
1. Verify project ID `el-kimiya`, Spark/no billing account, and the existing AI Logic + App Check configuration. Do not switch to Blaze. Confirm production reCAPTCHA domain and no debug token in production. The patch reuses the same Firebase app and App Check setup.
2. Authentication > Get started > Sign-in method: enable Email/Password and Google (choose support email). Authentication > Settings > Authorized domains: add `el-kimiya.vercel.app` and `localhost` for local testing. Keep the existing Firebase authDomain and Web configuration. Google popup may be blocked by browsers; email login is an alternative. Do not put passwords in source.
3. Firestore Database > Create database > default database > production mode. If you already have Firestore documents or custom rules, inspect/back up rules and merge the V8 matches before deploying; the supplied rules deny every unmatched collection. Do not blindly overwrite an existing production database's rules. This patch refuses to replace an existing local Firestore config.
4. From project root run `firebase login`, `firebase projects:list`, then `firebase deploy --only firestore:rules --project el-kimiya`. Review the target project before confirming. This deploys rules only, not hosting. If CLI is unavailable, use `npx firebase-tools deploy --only firestore:rules --project el-kimiya` or paste the reviewed rules into the Firestore Rules console and Publish. Check CLI exit code.
5. Run `npm run dev` and use the displayed localhost URL. Register one regular account and one separate account for Moduler. In Authentication > Users, copy the intended Moduler account UID. In Firestore Console create collection `v8Roles`, document ID equal to that UID, field `role` (string) = `moduler`. Only a trusted project owner should do this. No frontend can grant this role. Sign out/in if needed. Revoke by deleting that role document in console.
6. Use Moduler Studio to create bilingual draft, publish, edit and delete supplementary content. Publish a real source citation/URL/CID. Content appears on Library (lessons/references), Practice (two-choice questions), Flashcards (flip), and Molecular Lab (reference cards, not new 3D model geometry). Configured bilingual tutor guidance is appended to the actual main Tutor prompt. It does not change model, routing, Teach-Back prompts, or training.
7. Account panel offers manual, explicit private cloud backup/restore for selected progress keys and opt-in notes/cards. It does NOT provide continuous sync, per-account isolation of old browser storage, or migration of all historical storage. Cloud backup is one snapshot, overwritten by subsequent saves; restoring replaces only included local keys. Avoid shared devices; never include private book excerpts without permission. User management/role grants remain in Firebase Console, not in the app. No global analytics fake counters.
8. Verify App Check for Firestore in monitoring first; if enforcing, test both guest and signed-in access to published content. Existing Firebase AI App Check must remain functional. Public content is intentionally public, including answer keys; this is formative learning, not a secured examination.

## QA gate
- TypeScript / Vite build / V8 source check pass; also run existing `npm run test:source` and `node scripts/check-v71.mjs` if compatible with the new profile labels. Old snapshot-style checks may need updating; do not disable them blindly.
- Desktop: Settings tabs, About, Profile and Moduler preserve primary sidebar; no secondary vertical navigation. Mobile: existing bottom navigation remains; test 360 px width and both themes/languages.
- Guest may read published content, cannot see drafts or Moduler. User can log in, reset password, back up own progress, restore and sign out. Separate user cannot read the other user's cloud backup, cannot write content or roles.
- Moduler can create/edit/publish/unpublish/delete content; public UI updates. Role revocation denies subsequent writes. Validate draft isolation, query limit and direct URL access; use Firebase Rules Playground/Emulator before deployment.
- Create one real bilingual item of each kind and verify in the corresponding learning section. Test AI Tutor with a distinctive safe curator instruction; actual inference source must be returned by SDK. Test cloud and on-device separately, then prefer-device fallback. Never claim offline from UI toggles.
- Build and test Vercel preview; only then deploy production. Review git diff and never commit `.env`, tokens, private PDFs or backups. No automatic push is done.

## Limits
The V8 patch adds a functional supplemental CMS; existing compiled V7 datasets remain unchanged. It does not edit all old course objects, build 3D geometry for CMS molecules, provide account-isolated local storage, or sync private notes automatically. Free-tier quotas apply; the installer does not enable billing. The full Firebase runtime, rules compilation, browser QA and Android are not verified by the patch generator. Keep Android unchanged until Web QA passes.

## Optional local security integration test
With Firebase CLI, Java and Node installed, run from project root: `firebase emulators:exec --only auth,firestore --project demo-elkimiya-v80 "node scripts/test-v80-rules.mjs"`. This uses the demo project and refuses nonlocal emulator addresses. It requires first-time emulator downloads and does not touch production. Execute before deploying rules.
