# El-Kīmiyā Web V8.1 — access flow

Requires installed V8.0 (commit d02b563 or matching source). No changes to Firebase rules, database schema, API, Android, existing brand SVGs, or environment variables. Uses the already enabled email/password provider and existing v8Roles documents. Google sign-in was removed from the application, not from the Firebase project settings. No credentials in this patch.

## Entry and roles
- Landing → Sign in, Register or guest introduction. Auth pages have no learning sidebar. Sign-in redirects only after Auth and server-confirmed Firestore role lookup. Missing role document = learner. Cached role data is not used to grant privileged access. A role lookup failure blocks entry and shows retry/sign-out. An authenticated workspace needs an online role check at startup. A learner already verified in the same session can continue when the role listener reports cached metadata; Moduler requires live role confirmation.
- Guest must explicitly enter guest workspace. Sign-in and guest exit clear the per-tab guest-entry flag. Public previews from the landing page ask for guest entry first. Back to homepage from auth does not grant guest access.
- Learner has original learning workspace and account panel. Moduler has a separate responsive shell and overview, individual content sections, AI guidance, account and about pages. CMS remains supplementary (up to 100 loaded documents); no fabricated metrics and no migration of static course data.
- Signed-out pages cannot render Moduler UI. Firestore rules remain the real authorization layer; client guard is not a security boundary.

## Local storage
Source-level direct localStorage reads/writes are redirected through a scoped adapter (except boot/theme and adapter internals). Existing unscoped data remains untouched as legacy data, but is not automatically displayed in the new workspaces; it may include pre-V8.1 signed-in data of unknown ownership. New guest data and signed-in data use separate namespaces, with signed-in data keyed by UID. Old progress can be recovered manually after identifying its owner; no automatic migration is performed. Theme, language, collapsed-sidebar and reduced-motion preferences remain device-wide. A UID change reloads the document, preventing stale React state from being reused. This is application-level isolation, not encrypted storage or protection from another person who can inspect the browser. Other storage mechanisms and private PDF session behavior are not changed. Cloud backup remains manual and optional; no automatic upload or migration. Reset does not work for example-only email addresses. Shared demo accounts should contain synthetic learning content only; do not publish Moduler credentials, and rotate/revoke after judging.

## QA
Run installer, `node scripts/check-v81.cjs`, `node scripts/check-v80.mjs`, `npm run typecheck`, `npm run build`. Use normal Chrome and a separate incognito window. Confirm auth page has no learner navigation, back returns to landing, guest entry requires confirmation, guest exit returns to landing, direct #moduler as guest/user does not expose CMS, learner login routes to dashboard, Moduler login routes to studio, each Moduler menu controls the real section, save draft/publish/verify/delete a synthetic item, sign-out returns to landing, browser back cannot reopen privileged UI. Verify local note/counter isolation after switching accounts; verify backup only by explicit action. Check narrow screen, ID/EN and dark/light. Verify hybrid inference separately (no source claims from UI alone). Firestore rules deployment is not needed if V8.0 rules already deployed.

The installation makes backups under private/web-v81-backups. Review git diff, stage only Web changes, then commit and push to trigger Vercel. Do not stage Android, .env, tokens, reports, or private data.
